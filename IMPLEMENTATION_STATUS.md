## Workflow invariants

- Company scope comes from authenticated membership and composite foreign keys.
- The auth guard rereads membership/user state on every protected request, so deactivation and role changes apply to existing JWTs.
- Only owners assign privileged roles. An owner cannot remove their own access; the last active owner is protected.
- Sensitive workflow writes use transactions and audit events. Clocking, approvals, payment and balance updates use serializable isolation.
- Leave submission recalculates eligibility and working days using current settings. Invalid/stale drafts stay drafts. Negative manual adjustments cannot consume approved or reserved balance.
- Claims marked PAYROLL cannot use standalone bank payment.
- Claim submission revalidates settings and the active manager and freezes the policy/receipt IDs. All claim transitions retain actor/time/status/comment events. Receipt archive and submission run with serializable isolation so a required receipt cannot disappear during successful submission.
- File filters never widen authorization; archiving retains bytes and submitted claim receipts remain locked. Only CLEAN files, or explicitly allowed UNSCANNED files in development, can be downloaded.
- Unlinked members without an applicable administrative role receive no file metadata or approval queue entries; this is enforced explicitly rather than relying on an empty ORM permission filter.
- Preflight is informational and always reports the unfinished PCB and payroll engines. There are no calculate/approve/publish/pay payroll endpoints yet.
- PCB has a standard 2026 resident/non-resident preview with normalized inputs and calculation traces. Source worked examples are tested, but relief/exemption eligibility, TP1/TP3 resolution, special tax regimes, full LHDN conformance and payroll integration remain unfinished. Preview results do not clear the preflight blocker.
- The catalog contains EPF Parts A/C/E tables and above-threshold formulas, Part F, capped EIS/SOCSO and separate LINDUNG tables. Percentage previews retain the combined rounded total and an unallocated remittance difference; payroll totals assign that difference to company costs under the user-confirmed policy. Catalog imports remain inactive drafts with artifact/checksum provenance. EPF hashes identify extracted data; EIS/PERKESO hashes identify original PDFs. Arbitrary external import hashes are still caller-supplied. Eligibility and remaining statutory engines are unfinished; previews do not establish full statutory compliance.

## Database and seed

All implemented models and payroll groundwork are consolidated into `prisma/migrations/20261028132921_init/migration.sql`. All application table names are lowercase snake_case. The init includes a partial attendance uniqueness index and extra check constraints that must be preserved when regenerating SQL.

The user plans to recreate the development database. An already-applied older init is not upgraded by these edits. The application database has not been migrated or reset by this work.

The seed creates one company, owner user and OWNER membership. It requires the three SEED_* variables and a password of at least eight characters. It refuses to overwrite an existing login and does not create demo payroll data. See [README](README.md) for the fresh-database commands.
